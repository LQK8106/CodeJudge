## 4. 主要风险（按影响排序）

| # | 风险 | 影响 | 现状 | 关闭条件 |
|---|---|---|---|---|
| 1 | 生产凭据仍是开发占位值 | 密钥泄露即可伪造身份、直连数据库 | 未轮换（D1） | 按 `docs/LAUNCH-CHECKLIST.md` A1 重新生成并跑 preflight |
| 2 | 告警通道未配置 | 故障无人知晓，监控形同虚设 | fail-closed 已验证，真实通道未接（D2） | 触发测试告警 90s 内送达 |
| 3 | 全站未启用 HTTPS | 登录凭证与 token 明文传输 | 未执行（D3） | 无混合内容、SSE 逐字输出正常 |
| 4 | 判题容量未决策 | 0.95 题/s 且不随实例线性扩展，高峰期积压 | 已拍板方案 A（2026-11-16，接受现容量）；150 条复测未跑 | 完成 C4-4 复测后回填 B6/D4 |
| 5 | 容量只有同机下界 | 3 108.8 req/s 不能作为生产承诺 | 未用独立压测机复测 | 按 `perf-test/RUNBOOK.md` 双机复测并重标告警阈值 |
| 6 | refresh token 不可吊销 | 登出/改密/禁用后 token 仍有效 | 暂缓（DEFECTS 暂缓-1） | 引入 `jti` 轮换与吊销名单 |
| 7 | AI 评测无人类金标准 | “均分”不能等同于真实质量 | 已声明边界 | 引入人工抽样标注或明确不对外宣称准确率 |

## 5. 放行建议

| 场景 | 建议 | 前置条件 |
|---|---|---|
| 内部验收 / 作品演示 | 可放行 | 保持当前证据快照，演示环境使用独立凭据 |
| 受控内测（白名单、非公网） | 有条件放行 | 完成 D2 告警通道、D3 HTTPS，并锁定演示账号 |
| 公开发布 | 暂不放行 | D1–D4 全部关闭 + 独立压测机容量复测 + refresh token 方案拍板 |

**发布检查动作**：完成 D1–D4 后，重跑 `mvn verify`、Vitest、`verify-p6.py`，并在 `RELEASE-GATE.md` 中把对应行改为 PASS；任一阻断项未关闭，不得对外宣传“已上线/生产可用”。

## 6. 对外表述建议（避免过度承诺）

可以说的：
- “525 个自动化单测 + 264 项端到端断言全部通过。”
- “同机压测下恒定负载 3 108.8–3 266.5 req/s、0 错误，相对 500 req/s 门槛有 6.2× 余量。”
- “1 小时长稳 8 879 545 样本、0 错误。”

不建议说的：
- “生产可承载 3 000+ QPS”——同机压测只是下界，未做双机标定。
- “AI 点评准确率 4.07/5”——该分数是同一 LLM judge 的评分，且可执行性仅 2.98，无人文金标准。
- “已上线/生产就绪”——4 项生产阻断未完成。

## 7. 结论边界

本报告的“通过”仅指**代码与测试证据满足既定门槛**，不代表生产环境已验证。所有性能数字受同机部署、固定工作量脚本与 1 小时观察窗限制；AI 质量结论受 judge 有效性与无人类金标准限制。上述边界已在 `TEST-REPORT.md` §7 与 `RELEASE-GATE.md` §2 逐条登记。
