| 题库链路 | PASS 0.5s | PASS 0.8s | PASS 1.1s | `.cj-panel__table` 渲染 + 行数 > 0 |
| 提交判题链路 | PASS 4.3s | PASS 4.5s | PASS 5.1s | 竞赛详情「已报名」→ 编辑器写入 AC 代码 → 提交 → 轮询终态（WS 推送为主、「刷新状态」兜底）→ **判定「通过」** → 进入判题详情且用例行数 ≥2 |
| AI 点评链路 | PASS 11.4s | PASS 10.5s | PASS 13.8s | 详情页点「生成 AI 点评」→ 首帧正文 60s 内出现 → 120s 内进入「生成完成」且正文 >20 字符（真实 SSE 流式） |

## 4. 过程中真实出现的两次失败（均已定位，不是产品缺陷）

为保持「失败不掩盖」的原则，记录两次在准备阶段出现、并被归因的失败：

| 现象 | 归因 | 处理 |
|---|---|---|
| `[firefox] browserType.launch: can't open file for write !`（Firefox 进程启动即退出） | **环境限制**：后台 shell 受沙箱写权限约束，Firefox 无法写临时 profile；Chromium/Edge 恰好不需该路径 | 改为前台执行同一命令，Firefox 正常启动（155.0），最终 5/5 通过 |
| `[firefox] 提交判题链路：strict mode violation: getByText('竞赛提交') resolved to 2 elements` | **用例缺陷**：全文本匹配同时命中顶部导航「竞赛提交记录」与编辑器提示「竞赛提交（contestId=…）」；该提示是否渲染取决于页面加载时序，故只在 Firefox 暴露 | 用例改为正则精确匹配 `竞赛提交（contestId=<id>）`，语义未变、断言更严；随后三个浏览器全量重跑 15/15 通过 |

> 判定原则：浏览器启动异常先归「环境限制」，页面可渲染但定位器撞车归「用例缺陷」，只有「断言在真实 DOM 上不成立」才归「产品缺陷」。本次无产品缺陷。

## 5. 复现命令

```bash

docker compose --profile app up -d

# 1) 建竞赛 + 为三个学员报名（输出 E2E_CONTEST_ID）
cd judge-web
node e2e/setup-contest-matrix.mjs

# 2) 一条命令跑三浏览器 × 五流程
```

## 6. 覆盖边界（不夸大）

- 只覆盖**一条主链路**（登录/题库/提交/点评/榜单），不含断线重连、并发多人抢榜、弱网、移动端视口。
- 提交语言固定 Java（`4001` A+B），浏览器差异主要体现在 DOM/事件/存储与 SSE，不需要为语言矩阵扩测。
- 榜单断言「过 1 题」依赖「每场每学员只 AC 一次」的夹具前提；若后续用例给同一学员加 AC，需要同步调整断言口径。
- `edge` 走真实系统 Edge，故其版本随宿主机升级而变；报告中的版本是**本次实测版本**。
